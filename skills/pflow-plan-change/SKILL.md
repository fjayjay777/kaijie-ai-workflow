# Plan a Change

1. Read the relevant project instructions and inspect the existing behavior.
2. State the requested outcome, affected modules, assumptions, and acceptance criteria.
3. Choose the smallest implementation that meets those criteria.
4. Identify concrete verification commands from the project's existing tooling.
5. Ask about unresolved requirements only when the answer changes the implementation.

Output a concise plan with observable success criteria. Respect approvals already given by the user.
